## 5. Clinical AI Review Button & Human-in-the-Loop Popup *(Future — Do Not Start)*

### What Mai Wants
A single **"Run Review"** button inside the clinical workspace that silently triggers AI analysis across the active session, then surfaces all AI-generated decisions in a clean **list or popup for Mai to approve, edit, or reject** — one by one.

No "AI" labels, banners, or headers anywhere in the UI.

### UI Behaviour
- A discrete **"Run Review"** button (icon only or subtle label, e.g. a sparkle/refresh icon) sits in the session workspace toolbar — not in the header.
- On click: a **full-screen overlay / modal** opens with a scrollable list of AI draft decisions.
- Each item in the list shows:
  - **Section** (e.g. "Clinical Summary", "Action Plan", "Emotional Dynamics")
  - **Draft content** generated by AI
  - **Three actions**: ✅ Accept · ✏️ Edit → Save · ❌ Dismiss
- Accepted/edited items are written to the `ai_clinical_drafts` table with `status = 'accepted'`.
- Dismissed items are marked `status = 'dismissed'` and never surface again for that session.
- Mai can close the popup at any time; unreviewed items persist and re-appear next time she runs the review.

### What AI Analyses
Per session, the AI drafts:
1. **Session Summary** — key themes and outcomes in clinical language.
2. **Action Plan items** — suggested next steps for parent and coach.
3. **Emotional Dynamics tags** — stress level, polyvagal state, behavioural triggers, parental strengths.
4. **Client Persona update** — if new patterns emerge that update the child/parent profile.

### Data Architecture
- All drafts live in the `ai_clinical_drafts` table (schema already designed in `ai-clinical-notes-assistant-plan.md`).
- The Edge Function `session-ai-analyzer` calls Gemini (via `supabase/functions/_shared/gemini.ts`) with the raw session notes as input.
- Edge Function is called **only when Mai clicks "Run Review"** — never automatically in the background.
- Results are never committed to clinical records until Mai explicitly accepts them.

### Key Constraints (Non-Negotiable)
- ❌ No "AI", "Gemini", "Generated", or "Automated" labels visible to Mai.
- ❌ No automatic background processing — always manual trigger.
- ❌ No accepted items bypass the review popup.
- ✅ Every accepted draft is logged with `reviewed_by`, `reviewed_at`, and the original AI output preserved for audit.
- ✅ Mai can edit any draft before accepting — the edited version is what gets saved.
- ✅ The popup must not scroll at the window level; it uses internal list scrolling within the overlay.

### Implementation Order (When Ready)
1. Write `supabase/migrations/YYYYMMDD_ai_clinical_drafts.sql` (table + RLS).
2. Build `supabase/functions/session-ai-analyzer/index.ts` Edge Function.
3. Build `AdminClinicalDraftReviewModal.tsx` component (popup UI).
4. Wire the "Run Review" button into `AdminSessions.tsx` toolbar.
5. Connect accepted/edited drafts back into the relevant clinical section state.
6. E2E test with a real session note.
